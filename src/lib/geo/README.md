# `lib/geo` — WorldMap

An interactive SVG world map (built on [`react-simple-maps`](https://www.react-simple-maps.io/)) that plots animated route arcs between coordinate pairs on a real, pannable/zoomable globe. It ships with a departures legend, live stats footer, per-country info popup, and full dark-mode awareness.

The sample data baked into this folder is airline routes (airport codes, passenger counts), but the component itself only cares about **weighted edges between two points on a map** — see "Reusing this for non-aviation data" below.

## Files

| File | Purpose |
|---|---|
| `WorldMap.jsx` | The component. Renders the map, legend, controls, stats bar, and country popup. Default export, wrapped in `React.memo`. |
| `WorldMapHelper.jsx` | Sample location data (airport ↔ country ↔ coordinate maps) + pure helper functions (`processRouteData`, `buildRouteArcs`, `matchCountryToGeo`, formatting helpers). |
| `colorConfig.js` | Shared color ramp (`colors`) used for the departures/arrivals bars. Independent copy from `widgets/colorConfig.js` — not shared between the two folders. |
| `index.js` | Re-exports `WorldMap` plus the helper functions/constants from `WorldMapHelper.jsx`. |

## What data it expects: the `allCities` prop

```jsx
<WorldMap allCities={allCities} isMobile={false} />
```

`allCities` is a flat array of **route legs** — one entry per departure→arrival pair, not per city:

```ts
type RouteLeg = {
  departureCode: string;   // e.g. "MGQ" — matched case-insensitively, trimmed
  arrivalCode: string;     // e.g. "NBO"
  passengers: number;      // edge weight — summed when the same pair repeats
  flightCount?: number;    // optional; defaults to 1 per leg, summed into mapStats.totalFlights
};
```

That's it — `isMobile` is the only other prop, and it only controls whether the left departures/legend rail renders (`isMobile ? "hidden" : "flex"`); nothing else in the layout responds to it. Unlike `RankedDataWidget`, `WorldMap` does **not** measure the viewport itself — the caller decides `isMobile`.

### How `allCities` is turned into the map (from `WorldMapHelper.jsx`)

**`processRouteData(allCities)`** (drives the legend, popup, and stats bar):
1. Normalizes both codes (`trim().toUpperCase()`).
2. Looks up each code in `AIRPORT_TO_COUNTRY`. **If either code isn't in that map, the entire route leg is silently dropped** — there is no "unknown" bucket.
3. Builds a per-airport record (`departingPassengers`, `arrivingPassengers`, `totalPassengers`, its `[lon, lat]` from `CITY_COORDINATES`), then rolls airports up into a per-country record (`countryData`) with a summed total, a `color` from `COUNTRY_COLORS`, and a `coordinates` centroid from `COUNTRY_COORDINATES`.
4. Also returns `mapStats` — global totals (`totalPassengers`, `totalFlights`, `totalArrivingPassengers`, `totalDepartingPassengers`) shown in the bottom stats bar.

**`buildRouteArcs(allCities, limit = 18)`** (drives the animated flight-path layer, independent of the above):
1. Same drop-unknown-airport rule.
2. Collapses direction: `MGQ→NBO` and `NBO→MGQ` are merged into **one arc** keyed by the two codes sorted alphabetically (`"MGQ-NBO"`), with passenger counts summed across both directions.
3. Sorts pairs by summed passengers descending and keeps only the top `limit` (default 18) — busiest routes only, to keep the map legible.
4. Each arc gets a `weight` (0–1, its passengers ÷ the busiest pair's passengers), which drives arc stroke width, opacity, and the travelling-pulse animation speed. The bowed path itself is generated by a local `arcPoints()` sampler (a sine-lift between the two points, always bowing north).

Because both functions apply the exact same "drop if either airport code is missing from `AIRPORT_TO_COUNTRY`/`CITY_COORDINATES`" rule, a route leg either appears in **both** the legend/popup and the arc layer, or in neither.

## Reusing this for non-aviation data

The airport-coded sample data is not special-cased into `processRouteData`/`buildRouteArcs` themselves — those functions are generic "two codes + a weight" aggregators. What *is* aviation-specific is the lookup data they read, all exported as plain consts from `WorldMapHelper.jsx`:

- `AIRPORT_TO_COUNTRY` — code → country name (drives choropleth coloring + which codes are considered "known")
- `AIRPORT_TO_NAME` — code → display name (shown in the country popup's airport list)
- `CITY_COORDINATES` — code → `[lon, lat]` (marker + arc endpoint placement)
- `COUNTRY_COLORS` / `COUNTRY_COORDINATES` — country name → swatch / centroid
- `COUNTRY_NAME_MAPPINGS` — reconciles GeoJSON country names with your country keys (e.g. `"United Arab Emirates" → "UAE"`)

To point this at a different origin–destination network (warehouse→store shipments, migration corridors, cargo lanes, support-ticket routing between regional offices, etc.), replace these five/six consts in `WorldMapHelper.jsx` with your own code→country / code→name / code→coordinate maps, and shape your data as `{ departureCode, arrivalCode, passengers }` using **your** codes instead of IATA airport codes. `passengers` is just the numeric weight field — call it that even if it means "units shipped" or "tickets routed."

**Important caveat:** these maps are **not props** — `WorldMap.jsx` and `WorldMapHelper.jsx` both `import` them directly, so repointing the map means editing this folder's source, not passing new data in from a consuming app. Two other things are hardcoded directly in `WorldMap.jsx` (not just the helper) that a non-Somalia reuse should know about:
- **Somalia/Somaliland are always merged** into one landmass with a fixed `SOMALIA_COLOR` (`#058B4C`), and UAE is always aliased from `"United Arab Emirates"` — both via name checks inside `WorldMap.jsx` itself (`geoCountryName`, the `Geographies` render loop, and the popup logic all special-case these two).
- **On first load, the map auto-clicks and zooms into Somalia** (`didLock` ref, inside the `Geographies` render callback) once its geography and processed data are both ready — showing its info popup and a "Locked" badge by default. For a non-Somalia dataset this default-lock behavior should be removed or repointed at whatever entity should open focused.
- The base geography itself (`GEO_URL`, a `world-atlas` TopoJSON pulled from jsdelivr's CDN) is also a hardcoded import, not a prop — the map needs network access to that CDN to render any countries at all.

## Sizing — give it a large card

The root element is `className="h-full min-h-[350px] ..."` — it stretches to fill its parent's height (so the parent must have a defined height for `h-full` to do anything) with a hard floor of **350px**. Inside, the `ComposableMap` itself scales to 100%×100% of that box.

At any reasonable size, the map is simultaneously carrying: a 152px-wide departures/legend rail (left), zoom/route-toggle controls (top-right), a 236px-wide country info popup (top-right, up to `calc(100% - 8rem)` tall, appears on hover/click), and a stats bar spanning the bottom. In a small bento tile these overlays collide and the underlying geography has no room left to read. Treat `WorldMap` as a **wide or tall centerpiece** — a full-width dashboard section or a large single-column card — not a small multi-up tile.

## Dark mode

Follows the host app's `.dark` class on `<html>` (via the shared `isDarkMode()` util), not the OS `prefers-color-scheme` — same convention as the rest of this kit. All map colors (ocean, land, arcs, panels) are resolved from the `PALETTES.light` / `PALETTES.dark` objects at the top of `WorldMap.jsx` in JS, not CSS variables, because SVG presentation attributes can't read `var()`.

## Peer dependency

`react-simple-maps` (`^3.0.0`) and `lucide-react` are both already listed in this package's `package.json` `dependencies` — no extra install needed when consuming from `chart-kit`. If you copy `WorldMap.jsx`/`WorldMapHelper.jsx` out into another project standalone, you'll need to install both yourself (`react` and `react-dom` are this package's only declared `peerDependencies`).

## Usage

```jsx
import { WorldMap } from "chart-kit/lib/geo";

const routeLegs = [
  { departureCode: "MGQ", arrivalCode: "NBO", passengers: 18400, flightCount: 62 },
  { departureCode: "MGQ", arrivalCode: "DXB", passengers: 9200, flightCount: 30 },
  { departureCode: "HGA", arrivalCode: "JED", passengers: 5100, flightCount: 18 },
  { departureCode: "EBB", arrivalCode: "MGQ", passengers: 3300, flightCount: 12 },
];

function RoutesSection() {
  return (
    <div className="h-[560px] w-full">
      <WorldMap allCities={routeLegs} isMobile={false} />
    </div>
  );
}
```
